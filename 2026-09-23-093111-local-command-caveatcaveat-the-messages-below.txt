     3. Example of a quiz with anti‑cheat

     1. Setup – A teacher creates a latihan-kuis component in a page, setting:
        - appsScriptUrl → endpoint that logs scores.
        - kkm → 75.
        - duration → 300 seconds.
        - questions → array of AKM‑style multiple‑choice items.
        - allowRetake → true (optional).
     2. User starts the quiz (_mulaiLatihan):
        - The component generates a unique session token (_sessionToken) and
          stores it in localStorage.
        - It logs timer_mulai to the backend (via logActivity), recording start
          time, duration, material code, and student ID.
        - The timer component (timer-kuis) begins counting down.
     3. During the quiz:
        - Answer submission (_pilihJawaban / _submitMultiAnswers / _submitPGK /
          _submitShortAnswer) records answer time, checks for suspicious timing
          (< 3 s) and logs suspicious_timing if triggered.
        - Tab switching – If the user opens another tab, visibilitychange fires;
          the component increments _tabSwitchCount. After 3 switches, it logs
          curang_tab_switch.
        - Copy / paste attempts – While the quiz is active, any copy or paste
          triggers copy_paste_attempt logging.
        - Full‑screen exit – Leaving fullscreen while the quiz is running logs
          fullscreen_exit.
        - Timer expiration – When the timer reaches zero, _onWaktuHabis fires:
          - Checks if remaining time > 60 s (possible browser throttling) → logs
            time_manipulation.
          - Calls kuis-ledakan._selesaiKuis() which:
            - Sends a dasbor-kuis-log event with the final score, session token,
              and aggregated audit data.
            - Clears the session token and attempt counter.
            - Sends the final result to the Google Apps Script via logActivity
              (payload includes score, student ID, material code, timestamps,
              and audit summary).
        - Remidi – If the final score is below the KKM, the component can
          automatically load a remedial question set (remidiSoalUrl) and start a
          new attempt, respecting the same anti‑cheat checks.
     4. Result – The user sees a “Selesai” card with the score, possible
        “Remidi” button, and a link to the spreadsheet. The backend records the
        attempt, the number of retries, and any anti‑cheat flags (tab switches,
        copy attempts, time anomalies).

     Proposed Explanation

     - kuis-ledakan is a reusable, HAX‑editable web component that wraps a quiz
       engine (QuizEngine) and a question renderer. Its HAX properties make it
       easy for non‑developers to configure titles, URLs, material codes, answer
       shuffling, and UI visibility options directly from the HAX editor.
     - Anti‑cheat in latihan-kuis is built on several layers:
       a. Session isolation via a cryptographically‑generated token that is
          validated on every action and sent to the server.
       b. Time‑based checks (timer, remaining‑time threshold) to detect abnormal
          pauses or background‑tab throttling.
       c. Behavioral telemetry (tab switches, copy/paste, fullscreen exit)
          logged locally and flushed once per session.
       d. Locking mechanisms (lockAfterComplete, allowRetake) to prevent
          unlimited re‑tries and to enforce single‑attempt rules when needed.
     - The example flow shows how these layers work together: a user starts a
       timed quiz, answers questions, and the system records timing, navigation,
       and any suspicious behavior before finalising the attempt and sending
       the result to the teacher’s spreadsheet.

         _startQuiz().

       - Konflik CSS (mis‑display:none atau visibility:hidden pada elemen
         timer-kuis).
       - Error JavaScript di console (mis‑import timer-kuis.js atau
         kuis-ledakan.js yang gagal).

         allowRetake tidak sesuai.
